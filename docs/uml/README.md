# UML-диаграммы Adaptive AI Planner (по ТЗ v12)

| Файл | Что внутри |
|---|---|
| `Диаграммы_последовательностей_и_активности.pdf` | SD-01–SD-13 и AD-01–AD-06, по одной на страницу |
| `Описание_диаграмм_последовательностей_и_активности.docx` | Краткое описание каждой диаграммы и таблица «ФТ → диаграммы» |
| `uml class.docx` | Диаграммы классов CL-01 (сущности) и CL-02 (сервисы) с описанием |
| `png/` | Все диаграммы картинками |
| `puml/` | Исходники PlantUML. `style.iuml`, `seqhead.iuml` и `CL-01_entities.iuml` держать рядом |
| `legacy/` | Архив: варианты использования по старой версии ТЗ, в проекте не используются |

| Диаграмма | Что показывает |
|---|---|
| UC-01, UC-02 | Варианты использования: учётная запись, задачи и цели; календарь, ОРИОКС, нагрузка и ИИ |
| CL-01 | Сущности и связи (те же, что в базе данных) |
| CL-02 | Сервисы серверной части и их операции |
| CD-01 | Компоненты: браузер, сервер, PostgreSQL, файловое хранилище, внешние сервисы |
| LD-01 | Уровни архитектуры |
| SD-01–SD-13 | Последовательности основных сценариев |
| AD-01–AD-06 | Активности |

Перерисовать: `java -DPLANTUML_LIMIT_SIZE=16384 -jar plantuml.jar -tpng -o ../png puml/*.puml`
(из папки `docs/uml`) или плагин PlantUML в VS Code / IntelliJ.

- UC — варианты использования
- SD — последовательности
- AD — активности
- CL — классы
- CD — компоненты
- LD — уровни архитектуры

Номера ФТ в заголовках диаграмм соответствуют ТЗ v12 (`docs/ТЗ_Adaptive_AI_Planner_v12.docx`).

## Как диаграммы связаны между собой

- Сущности описаны один раз в `puml/CL-01_entities.iuml`. Этот файл подключают диаграмма классов CL-01
  и модель данных `database/data_model.puml`, поэтому сущности в них всегда совпадают.
  Поля названы в camelCase, как в REST API; в базе данных (`database/postgresql`) те же поля в snake_case.
- Сервисы на CL-02, компоненты на CD-01 и участники диаграмм последовательностей названы одинаково
  (AccountService, TaskService, AIService и т. д.).
- Пути запросов на SD-диаграммах совпадают с контрактом REST API, а вызовы базы данных
  (`apply_decomposition`, `replace_lessons`, `calendar_overlaps` и др.) — с функциями и процедурами
  из `database/postgresql`.
