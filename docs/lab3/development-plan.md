# План разработки Adaptive AI Planner для ЛР №3

План подготовлен 3 ноября 2026 года по [ТЗ v12](../ТЗ_Adaptive_AI_Planner_v12.docx), [контрактам](../contracts.md) и [UML](../uml/README.md). Основа сверена с main `d6f4ebb397323839fe12bf00bec3b4d0431987e4`. Это план полного объёма проекта, а не заявление о готовности всех функций.

Для ЛР №3 предъявляются обоснование платформы, декомпозиция, задачи с порядком и приоритетами и индивидуальная работа с Git. Реализация остальных строк выполняется по последующим этапам проекта. Количество задач и распределение ролей не подтверждают личный Git-вклад пяти студентов.

## Правила планирования

- **P1 — высокий:** согласование интерфейсов, основа продукта и ключевой сценарий «цель → предложение → подтверждённые задачи». **P2 — обычный:** развитие остальных обязательных функций, интеграция, развёртывание и приёмка. Все действующие требования ТЗ остаются в плане.
- Сначала выполняются зависимости, затем выбирается готовая задача с более высоким приоритетом. При одинаковом приоритете возможна параллельная работа. Номер карточки GitHub отражает её создание и не задаёт очередь.
- Для каждой задачи указан один ответственный за результат. Свои изменения в интеграционных задачах выполняют владельцы модулей; тимлид координирует их объединение.
- Зависимость означает готовность нужного интерфейса/результата. UI в L3-13–L3-30 можно делать на моках после L3-02; подключение к настоящему серверу и проверка всех сценариев входят в L3-33.
- L3-06 выполняется по модулям небольшими PR: готовая часть слоя данных передаётся соответствующему сервису. Тесты добавляются в ходе реализации каждой карточки; L3-34 сводит проверки и покрытие после интеграции.
- «Основа в main» описывает найденные материалы, а не автоматически закрывает карточку. Завершение подтверждается её критерием, проверками и принятым PR. ФИО и GitHub-логины пяти ролей команда подставляет отдельно; чужое авторство не приписывается.
- Даты и оценки трудоёмкости не выдумываются: после оценки карточек команда задаёт сроки и при необходимости выравнивает нагрузку. Сроки не заменяют зависимости.

## Порядок и параллельная работа

1. **Основа:** L3-01 → L3-02 → L3-03/L3-04/L3-07; затем L3-05/L3-06, L3-08 и L3-09 по зависимостям из таблиц.
2. **Основной сценарий:** L3-10 → L3-11 → L3-12; параллельно Фронт 1 делает L3-13 → L3-14 на моках, Фронт 2 начинает L3-26 по контракту.
3. **ИИ:** после данных, авторизации и календарного интерфейса L3-23 → L3-25; реальный адаптер L3-24 можно подключать параллельно применению предложений. Сначала сценарий проверяется на заглушке.
4. **Остальные модули:** Бэк 2 ведёт файлы/профиль/snapshot, Бэк 3 — календарь/ОРИОКС/нагрузку, фронтенд готовит соответствующие экраны. Конкретная допустимая очередь указана в столбце зависимостей.
5. **Объединение:** L3-33; затем параллельно L3-34/L3-35/L3-36, по своим зависимостям L3-37 → L3-38 → L3-39; финальная приёмка L3-40.
6. **Git-демонстрация:** L3-41–L3-45 выполняются в ходе работы над собственными полезными изменениями и готовятся к защите ЛР3.
