# Подключение ОРИОКС первый этап

Откройте локальный сайт, войдите в аккаунт планировщика и выберите «ОРИОКС» в боковом меню. Введите логин и пароль ОРИОКС только в форму приложения, не в чат. После подключения появятся предметы текущего семестра, контрольные мероприятия, учебные недели и баллы.

Внешние запросы идут только на `https://orioks.miet.ru/api/v1` через backend. Пароль используется один раз для получения ключа и не сохраняется. Ключ хранится в `backend/data/accounts.sqlite3` в зашифрованном виде AES-GCM, связанном с владельцем аккаунта. Браузер ключ не получает. Отдельный ключ шифрования находится в `backend/data/orioks.key`: сохраняйте его вместе с базой при резервном копировании; не добавляйте в Git.

## Что работает

- Подключение, просмотр сохранённых учебных данных, обновление и отключение.
- Ключ запрашивается один раз при подключении. Повторная синхронизация его использует, не создаёт новый. У ОРИОКС лимит восемь ключей на студента.
- Если ключ уже получен, а первая загрузка предметов не удалась, он остаётся сохранённым. Для повторения используйте «Обновить», а не новое подключение.
- Данные заменяются только после успешной загрузки всего набора. При ошибке старая копия остаётся; интерфейс показывает время последнего обновления.
- Подключения и данные разделены по пользователям. Пароли и ключи не включаются в ответы, сообщения об ошибках и исходящие журналы приложения.
- «Отключить» отзывает только ключ этого приложения в ОРИОКС, затем удаляет локальное подключение и учебную копию. Задачи сохраняются. Если отзыв недоступен, подключение остаётся для повторной попытки.
- При отозванном ключе показано требование переподключения. При нехватке ключей приложение сообщает о лимите и ничего не удаляет из других приложений.
- Не больше пяти попыток нового подключения за 15 минут на аккаунт планировщика; параллельные подключения/синхронизации одного пользователя блокируются.

## Границы этапа

Контрольные мероприятия пока не превращаются в задачи. Неделя ОРИОКС показана как учебная неделя, не как точный дедлайн. Отсутствующий балл, ноль и пропуск различаются и не считаются автоматически признаком выполнения.

Следующий этап после проверки настоящих данных: расписание, объединение двух лабораторных пар в блок, привязка мероприятия к блоку, плановая дата сдачи и последнее занятие без снижения баллов. Будет отдельно указано, какой срок получен из источника, а какой рассчитан по правилу предмета.

Сейчас интеграция проверена на подставных ответах официального формата. Доступность настоящего endpoint проверена без авторизации: возвращается ожидаемый JSON с HTTP 401. Личные данные настоящего студента ещё не загружались — это проверяется подключением через форму.

Если реальная структура ответа отличается от документации, приложение показывает понятную ошибку и не сохраняет частичный набор. Не отправляйте в чат пароль, ключ или полный ответ с личными данными.

## API локального сервера

- GET `/api/v1/orioks/connection` — состояние и последняя учебная копия.
- POST `/api/v1/orioks/connection` — `{login, password}`, получить ключ и загрузить данные.
- POST `/api/v1/orioks/sync` — обновить копию с сохранённым ключом.
- DELETE `/api/v1/orioks/connection` — отозвать ключ и удалить подключение.

Все маршруты требуют входа в планировщик. Секреты в ответах отсутствуют. Схема PostgreSQL не изменяется: текущий адаптер использует локальную SQLite-базу.

Документация источника: https://orioks.gitlab.io/student-api/.
