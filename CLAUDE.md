# Adaptive AI Planner — памятка для Claude Code

Учебный проект по дисциплине «Конструирование программного обеспечения»: веб-планировщик целей
и задач для студентов с ИИ-ассистентом и интеграцией с ОРИОКС (НИУ МИЭТ). Команда из пяти человек.
Отвечай и пиши документацию, комментарии и сообщения коммитов по-русски.

## Актуальная архитектура — ТЗ v12

- Данные пользователя хранятся на сервере в PostgreSQL, файлы — в файловом хранилище сервера.
- Учётные записи: регистрация и вход по email и паролю, одни и те же данные на компьютере, планшете и телефоне.
- Браузер (React + TypeScript) работает с данными только через REST API сервера (FastAPI).
  В IndexedDB хранится лишь копия канбан-доски и календаря для просмотра без сети; изменять данные без сети нельзя.
- К языковой модели (внешний API) и ОРИОКС обращается только сервер.

## Стек и запуск

- Сервер: Python 3.13+, FastAPI, Pydantic, SQLAlchemy 2, Alembic, `uv` для окружения.
- База: PostgreSQL 15+ (нужен `ON DELETE SET NULL (столбец)`).
- Фронтенд: React + TypeScript (каркаса пока нет).

```sh
# сервер (из корня репозитория)
uv sync --project backend --frozen
uv run --project backend --frozen python -m uvicorn app.main:app --app-dir backend

# база данных: миграции Alembic (адрес — DATABASE_URL в .env, образец — .env.example)
createdb planner
uv run --project backend --frozen alembic -c backend/alembic.ini upgrade head
psql -d planner -f database/postgresql/tests/test_schema.sql   # «Все проверки пройдены»

# тесты сервера: PostgreSQL поднимается в Docker (testcontainers);
# вместо Docker можно указать пустую базу в TEST_DATABASE_URL
uv run --project backend --frozen pytest backend/tests

# диаграммы (из docs/uml)
java -DPLANTUML_LIMIT_SIZE=16384 -jar plantuml.jar -tpng -o ../png puml/*.puml
```

## Соглашения

- API: база `/api/v1`, JSON в camelCase, id — uuid, время — ISO 8601 с часовым поясом,
  статусы и приоритеты — коды из таблицы 1 ТЗ. Ошибки — `{"error": {"code", "message", "field"?}}`,
  коды перечислены в `docs/contracts.md`. Чужой объект — 404.
- База: snake_case, схема `planner`, у каждой таблицы `user_id`; ссылки между записями — составные
  внешние ключи `(x_id, user_id)`. Запросы всегда фильтруют по `user_id` текущего пользователя.
- Обработчики API не пишут SQL сами — только через слой данных (SQLAlchemy). Правила ТЗ проверяются
  в Pydantic, ограничения в базе — последняя линия защиты.
- Даты, просрочку, прогресс, пересечения и нагрузку считает код (или функции БД), а не языковая модель.
- Ключи и пароли — только в переменных окружения (`.env`, в репозитории — `.env.example`); в код и логи не попадают.
- Имена сервисов (AccountService, TaskService, AIService и т. д.) и их операции — как на диаграмме
  `docs/uml/puml/CL-02_servisy.puml`.

## Как вносить изменения

- В `main` напрямую не пушим: ветка → PR → одобрение одного участника → Squash and merge.
- Имена веток: `feat/…`, `fix/…`, `docs/…`. Сообщения коммитов: `тип(область): что сделано`
  по-русски, как в истории репозитория.
- Изменение контракта (API, схема БД, схемы ответов ИИ) — PR с меткой `contract`, его одобряют все стороны.
- Схема БД меняется только новой миграцией Alembic (`backend/migrations/versions`); уже применённые
  не правятся. Скрипты `database/postgresql/01–06` — снимок миграции 0001, их тоже не меняем.
- Сервисы работают с базой через репозитории `backend/app/db/repositories` (user_id — первый аргумент).
- Изменили сценарий или сущность — обновите `.puml` и перерисуйте PNG.
- Не меняй ТЗ (`.docx`) и архивные папки без явной просьбы.
