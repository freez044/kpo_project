# Почта для восстановления пароля

На странице входа нажмите «Забыли пароль?». Пользователь указывает email своего аккаунта, получает код и вводит его вместе с новым паролем.

## Какой ящик нужен

Нужен ящик отправителя: письма с кодами будут приходить пользователям от его имени. Каждый пользователь получает код на свой email, указанный при регистрации.

Для команды удобнее создать отдельный ящик проекта. Для локальной проверки допустим личный ящик, но доступ к нему позволит серверу отправлять письма от вашего имени. Обычный пароль от почты в чат и исходный код не передавайте.

## Подключение

1. Создайте ящик у выбранного провайдера.
2. В его настройках разрешите SMTP и создайте отдельный пароль приложения, если такая возможность поддерживается. Названия настроек зависят от провайдера.
3. Если в корне проекта нет `.env`, скопируйте туда `.env.example`. Существующий файл не заменяйте: добавьте настройки в него.
4. Заполните в `D:\kpo_project\.env`:

```dotenv
AUTH_SMTP_HOST=адрес_SMTP_сервера_провайдера
AUTH_SMTP_PORT=465
AUTH_SMTP_USERNAME=адрес_ящика_отправителя
AUTH_SMTP_PASSWORD=пароль_приложения
AUTH_SMTP_FROM=адрес_ящика_отправителя
AUTH_SMTP_STARTTLS=false
```

Адрес сервера и режим подключения возьмите в официальной инструкции провайдера. Обычно для STARTTLS: порт 587 и `AUTH_SMTP_STARTTLS=true`; для TLS с начала соединения: порт 465 и `false`. Незашифрованный SMTP не поддерживается.

5. Перезапустите backend по [LOCAL_START.md](LOCAL_START.md).
6. Создайте тестовый аккаунт с доступной вам почтой, запросите код, проверьте письмо и папку «Спам», затем установите новый пароль.

`.env` исключён из Git. SMTP-пароль не передаётся браузеру. Сейчас настройки не заполнены: реальная доставка писем не проверена. Подставной отправитель используется только в изолированных серверных тестах. Рабочий сайт без настройки SMTP показывает сообщение о недоступности отправки.

## Правила

- Код: 6 цифр, действует 10 минут, одно успешное использование.
- Пять неверных проверок исчерпывают код, но не блокируют обычный вход.
- Повторный запрос: не чаще раза в минуту и не более трёх запросов на email в час; действует дополнительный лимит по адресу клиента.
- Новый запрос заменяет предыдущий код. В базе хранится HMAC-хеш, а не открытый код.
- Ответ одинаков для существующих и отсутствующих аккаунтов: «Если аккаунт существует…».
- Доставка выполняется после ответа запроса. Если SMTP отклонит письмо, код не активируется; журнал содержит только общую ошибку без адреса и кода. Попадание письма во «Входящие» зависит от провайдера.
- Успешный сброс одной транзакцией меняет Argon2id-хеш пароля, расходует код, снимает блокировку неверных входов и отзывает все прежние сеансы. Задачи сохраняются.
- После сброса требуется войти заново. Подтверждение email при регистрации этим изменением не добавлено.

API: POST `/api/v1/auth/password/request` с `{email}` и POST `/api/v1/auth/password/reset` с `{email, code, newPassword}`. Без SMTP первый маршрут возвращает понятную ошибку 503.
