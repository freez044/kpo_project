# Локальная версия с аккаунтами

Проект: `D:\kpo_project`. Ничего не публикуется в GitHub.

## Запуск на этом компьютере

В первом терминале PowerShell:

```powershell
cd D:\kpo_project\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале (нужен Node.js 20.19+ или 22.12+):

```powershell
cd D:\kpo_project\frontend
node node_modules/vite/bin/vite.js
```

Открыть http://127.0.0.1:5173. Для остановки — Ctrl+C в обоих терминалах.

## Установка с нуля

Сервер аккаунтов работает с Python 3.12+; полный серверный проект с PostgreSQL требует Python 3.13+, как указано в pyproject.toml.

```powershell
cd D:\kpo_project\backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-local.txt
cd ..\frontend
npm install
```

Для полного окружения вместо установки requirements-local.txt: `uv sync --project backend --frozen` из корня проекта. Зависимости аккаунтов также включены в pyproject.toml и uv.lock.

## Что реализовано

- Регистрация по email, паролю, имени и фамилии; учебная группа необязательна.
- Вход и выход, восстановление сеанса после обновления страницы и перезапуска сервера.
- Проверки полей на клиенте и сервере; нормализация email; защита от повторной регистрации.
- Пароли хранятся как Argon2id-хеши. JWT действует 15 минут и находится только в памяти страницы.
- Refresh-токен хранится в HttpOnly/SameSite=Strict cookie; в базе — SHA-256-хеш. При обновлении токен заменяется, старый больше не принимается.
- Сеанс ограничен 30 днями с момента входа. Выход отзывает и refresh, и связанные access-токены; остальные устройства остаются в аккаунте.
- Пять неверных паролей подряд блокируют вход в существующий аккаунт на 15 минут. После истечения блокировки/успешного входа счётчик сбрасывается.
- API профиля возвращает только пользователя из проверенного токена. Общий старый демонстрационный /tasks отключён.
- Проверка сеанса раз в минуту и при возвращении к окну. Временная сетевая ошибка не выдаётся за успешный выход.

## Данные и границы этапа

Аккаунты и сеансы: `backend/data/accounts.sqlite3`. Ключ подписи: `backend/data/jwt.key`; автоматически создаётся один раз и сохраняется между запусками. Вся папка исключена из Git. Не удаляйте её, если хотите сохранить аккаунты; при резервном копировании сохраняйте и базу, и ключ.

Это отдельный адаптер SQLite для локальной разработки. Он пока не использует PostgreSQL-репозитории из `app/db`. Существующая схема PostgreSQL и её миграции не изменялись; подключение аккаунтов к ней — отдельный этап. SQLite-аккаунты автоматически в PostgreSQL не переносятся.

Задачи сохраняются в этой же SQLite-базе с владельцем user_id; доступны только после входа в соответствующий аккаунт. Реализованы создание, редактирование, статусы, категории, дата в плане, дедлайны и удаление с подтверждением. На главной: задачи на сегодня, просроченные и ближайшие сроки на 7 дней. Цели пока находятся только в памяти страницы и сбрасываются после обновления и выхода. Календарь и ИИ пока не подключены. Добавлен первый этап интеграции ОРИОКС: подключение и просмотр учебных данных — см. [ORIOKS_SETUP.md](ORIOKS_SETUP.md). Подтверждение email при регистрации и редактирование профиля пока не реализованы. Восстановление пароля по коду добавлено; для настоящих писем нужен ящик отправителя — см. [MAIL_SETUP.md](MAIL_SETUP.md).

Сервер предназначен для loopback-запуска на этом компьютере. Для размещения понадобятся HTTPS, AUTH_COOKIE_SECURE=true, настройка разрешённых источников, PostgreSQL, ограничение общего потока запросов и резервное копирование. HTTP cookie без Secure — исключительно для текущего локального запуска.

## API задач локальной версии

GET/POST /api/v1/tasks, GET/PATCH/DELETE /api/v1/tasks/{uuid}, GET /api/v1/dashboard. Нужен Authorization: Bearer. Чужая задача отвечает 404. Данные: title, description, category (название или null), priority, status, plannedDate (YYYY-MM-DD или null), deadline (ISO 8601 с часовым поясом или null). Локальная category пока является текстовым полем, а не categoryId PostgreSQL-контракта. Пустой plannedDate означает отсутствие дня в плане; при создании без поля берётся текущий день в часовом поясе пользователя. DONE ставит completedAt, повторный DONE не меняет дату; выход из DONE очищает её. DONE/CANCELLED не считаются просроченными. Дедлайн хранится в UTC и показывается в часовом поясе профиля. Неоднозначное время при осеннем переводе часов выбирается автоматически; несуществующее время при весеннем переводе отклоняется формой.


## Канбан-доска

Откройте «Канбан» в боковом меню. Доска использует те же сохранённые задачи, что главная и список задач.

- Колонки: «Без плана», «Запланировано», «В работе», «На паузе», «Выполнено», «Отменено».
- На компьютере карточку можно перетащить за свободную область; нужная колонка подсвечивается. Доска прокручивается по горизонтали.
- На телефоне колонки идут друг за другом. Статус можно выбрать внизу карточки; это доступно и с клавиатуры.
- Есть фильтры по категории (включая отсутствие категории) и приоритету; кнопка сброса возвращает все задачи.
- Нажатие на название открывает редактирование. Кнопка «+» создаёт задачу сразу с выбранным статусом.
- Карточка меняет колонку после ответа сервера. При ошибке статус не показывается как сохранённый.
- При переносе дата в плане, дедлайн и другие поля остаются прежними. Переход в «Выполнено» ставит completedAt, выход очищает его.


Создание учебных задач и расчёт двух сроков из ОРИОКС описаны в [ORIOKS_PLANNING.md](ORIOKS_PLANNING.md).
